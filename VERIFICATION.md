# Проверка Orbit Local Agent v2

Дата: 17 октября 2026. Node.js 24, Python 3 со стандартной sqlite3. Проверялся локальный запуск, не облачная симуляция.

## Основной сценарий

UI чата → `POST /api/agent` → `get_db_schema` → генерация SQL по найденной схеме → `execute_sql_query` → доменный анализ → поток NDJSON → журнал, ответ и график.

| Граница | Подтверждение |
|---|---|
| Сервер | `Orbit Local Agent · http://localhost:3000`, loopback, SQL planner |
| Источник | Физический `workspace/company.sqlite`, таблицы sales и candidates |
| Инструменты | В UI видны реальный SELECT, 96 прочитанных строк и время вызовов |
| Ответ | Сентябрь: 7 700 400 ₸ выручки, 3 187 967 ₸ прибыли, 41,4% маржи |
| SQL-редактор | COUNT / SUM вернули 96 записей и 14 532 600 ₸ за весь источник |
| Запрет записи | DELETE из интерфейса вернул ошибку разрешённого SELECT |
| Файлы | XLSX открыт из workspace без браузерной загрузки, отображено 50 строк предпросмотра |
| Смена источника | После выбора finance/sales.xlsx в UI изменился источник, метрики пересчитаны |
| Подключение | Через форму выбрана таблица sales; HR-файл очищен, кандидаты прочитаны из SQLite |
| Сохранение UI | Проверены широкая вёрстка 1280 px и компактная 650 px; на 1280 bodyWidth = innerWidth |
| Консоль | Список ошибок браузера пуст |

## Другие модули

- HR отобразил четыре кандидата из локального источника, профессиональные навыки и баллы.
- Коммуникации прочитали JSON-диалоги; серверный черновик о CRM вернулся в textarea. Старые фиксированные демо-цены из ответа удалены.
- SMM вызвал сервер, перечитал финансовый источник и сформировал пять черновиков с лидером продаж «Внедрение CRM».

## Автоматические тесты

`node --test tests/*.test.mjs`: **18 passed, 0 failed**.

Покрыты:

- реальное чтение схемы, SELECT, NDJSON и изменение ответа после изменения временной SQLite на диске;
- запрет DELETE / UPDATE / DROP / ATTACH / PRAGMA / расширений / stacked statements;
- байтовое сравнение базы до и после попыток записи;
- SELECT WITH, ограничение результата и прерывание бесконечного рекурсивного SQL;
- чтение CSV / JSON / XLSX / TXT; запрет traversal, абсолютных путей, скрытых файлов и symlink за workspace;
- настройка источника, ошибка подключения без замены активной конфигурации;
- HR / reply / content endpoints; проверка Origin, Host и Sec-Fetch-Site;
- отмена реального инструмента, построение SQL для нестандартных имён полей;
- Ollama tool loop: эмулируются только ответы модели, schema / SQL инструменты выполняются настоящие;
- арифметика, нулевая выручка, убыток, периоды, профессиональный скоринг.

Дополнительно успешно: синтаксические проверки JS-модулей и компиляция Python-исходника.

## Ограничения проверки

Настоящая Ollama-модель не установлена и не запускалась; адаптер проверен автоматическим тестом с подменой модельного HTTP-ответа. Коннекторы PostgreSQL / MySQL, старые XLS и отправка в Meta отсутствуют. Тестовая компания вымышленная; действительная база компании пользователем не предоставлена. Реальный доступ к пользовательской базе настраивается через workspace / SQLite path. Публичное демо v1 не получало доступ к диску.
