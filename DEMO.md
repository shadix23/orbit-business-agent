# Проверка Orbit Local Agent

1. `./start.command` → http://localhost:3000. В правой верхней части `Local workspace`.
2. **Аналитика → Схема и SQL.** В примере найдутся sales и candidates. Выполнить `SELECT COUNT(*) AS n, SUM(revenue) AS revenue FROM sales`: 96 строк, 14 532 600 общей выручки.
3. В том же окне `DELETE FROM sales` возвращает ошибку разрешённого SELECT. Исходные записи остаются неизменными.
4. **Агент → Проанализировать прибыль.** Раскрыть журнал: схема → генерация SQL → реальное выполнение → анализ → ответ. Сентябрь примера: выручка 7 700 400 ₸, прибыль 3 187 967 ₸, маржа 41,4%.
5. **Аналитика → Рабочая папка.** Открыть `finance/sales.xlsx`, затем выбрать его для финансовой аналитики. Графики покажут данные с диска, источник сменится на путь XLSX.
6. В чате: «Прочитай finance/sales.csv» или прямой SELECT. В результате виден настоящий файл / набор строк.
7. **HR** перечитывает candidates.json либо таблицу candidates; **Коммуникации** читает локальный JSON диалогов, кнопка генерации вызывает сервер. **SMM** вызывает сервер, который заново читает активный финансовый источник.
8. **Интеграции → Настроить подключение:** выбрать собственную рабочую папку и SQLite, при необходимости сопоставить поля. Новый контекст применяется сразу.

Для свободного tool calling установите локальную Ollama-модель отдельно и задайте её имя. Показ без LLM остаётся настоящим чтением БД и файлов, но использует ограниченный планировщик.
