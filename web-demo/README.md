# Orbit — Business Operating AI Agent

Рабочий демонстрационный MVP: командный центр агента, финансовая аналитика, HR, WhatsApp / Instagram и SMM. Интерфейс на русском, валюта KZT. Данные и персонажи вымышлены.

## Быстрый запуск

Нужен **Node.js 20+**. Внешних зависимостей и ключей API нет. На этом Mac можно сразу выполнить `./start.command`: launcher найдёт Node в PATH или использует встроенный runtime Codex.

```bash
cd orbit
npm start
```

Откройте **http://localhost:3000**. `PORT=4000 npm start` меняет порт. Сервер слушает только loopback `127.0.0.1`.

```bash
npm test        # тесты доменной логики и HTTP API
npm run check   # синтаксическая проверка
```

Можно запустить и статическую версию: `python3 -m http.server 3000 --directory dist`. Тогда автоматически включается browser mock. Открытие `index.html` через `file://` не поддерживается из-за ES modules.

## Что демонстрирует продукт

- **Обзор:** четыре вычисляемые метрики, график выручки и расходов, подсказка о крупнейшей статье затрат, история задач и статусы источников.
- **AI-агент:** запросы на русском, анимированные этапы выполнения, остановка задачи, журнал фактически выполненных операций, структурированный результат, график и экспорт Markdown.
- **Аналитика:** CSV/JSON до 5 МБ и 10 000 строк, проверка схемы, выбор периода, таблица, top-3 затрат, CSV-экспорт и возвращение к демо-базе.
- **HR:** 4 исходных резюме, добавление текста или TXT, поиск, объяснимый скоринг и шорт-лист. 70 баллов — четыре профессиональных навыка, до 30 — опыт до 5 лет. Решение о найме остаётся у человека.
- **Коммуникации:** входящие WhatsApp / Instagram, симуляция нового сообщения, контекстный шаблон ответа, редактирование и симуляция отправки. Опциональный автоматический черновик.
- **SMM:** пять публикаций разных форматов, выбор тем по лидирующему продукту, редактирование, одобрение в демо и экспорт.
- **Интеграции:** статусы `Simulated / Paused`, остановка симуляторов, название бизнеса, режим исполнения и сброс данных.
- **Сохранение:** localStorage в текущем браузере; данные сохраняются после перезагрузки. Сброс — в интеграциях.

## Архитектура и структура компонентов

```text
orbit/
├── dist/
│   ├── index.html       # shell, метаданные, точки монтирования
│   ├── style.css        # дизайн-система, сетки, адаптивность, анимации
│   ├── app.js           # Router / Store / представления / действия
│   └── engine.js        # доменная логика — общий модуль браузера и API
├── server.mjs           # Node HTTP API и статическая раздача
├── tests/
│   ├── engine.test.mjs  # импорт, периоды, расчёты, HR и маршрутизация
│   └── api.test.mjs     # отдельный сервер, HTTP, валидация и ошибки
├── demo-data/           # CSV / JSON / TXT для презентации
├── .openai/hosting.json # настройки статической версии Sites
├── ARCHITECTURE.md      # границы модулей и путь к production
├── DEMO.md              # сценарий демонстрации на 5 минут
└── package.json
```

View-функции `dashboard`, `agentPage`, `analytics`, `hr`, `messages`, `smm`, `integrations` компонуют `metricCards`, `chartCard`, `chartMarkup`, `runMarkup`, `heading`, `modal` и общие UI-примитивы. Использован HTML/CSS/JS вариант из задания: без сборщика и npm-зависимостей, иконки — встроенные SVG. Шрифт Golos Text загружается с Google Fonts; при отсутствии интернета используется системный шрифт.

Путь задачи: `AgentComposer → execute() → /api/agent или browser mock → resolveAgent() → analyze / scoreCandidate / generatePlan / generateReply → ExecutionLog + ResultCard`. Логи показывают операции и источники; скрытые рассуждения LLM не симулируются.

## Контракт импорта

CSV с `,` или `;`, поддерживаются BOM, кавычки и многострочные поля. JSON — массив объектов. Обязательные поля:

| Поле | Значение |
|---|---|
| `date` | Реальная дата `YYYY-MM-DD` |
| `revenue` | Число ≥ 0, выручка в ₸ |
| `cost` | Число ≥ 0, расходы в ₸ |
| `product` | Необязательное название продукта |
| `category` | Необязательная статья затрат |
| `channel` | Необязательный канал продаж |

Пример: `demo-data/sales.csv`. В строке `cost` — общая сумма расходов, отнесённых к этой записи, а `category` — статья этой суммы. Для разных статей нужны отдельные записи с корректным распределением выручки, чтобы не считать её повторно.

**Формулы:** прибыль = выручка − расходы; маржинальность = прибыль / выручка × 100. При нулевой выручке в интерфейсе выводится 0%, убыток показывается отдельно. Показатель «Прибыль» учитывает только расходы в файле: налоги и прочие обязательства необходимо включать в исходные данные самостоятельно. Рост — к предыдущему доступному месяцу в базе. Если его нет, сравнение недоступно. «Последний месяц» означает последний месяц **в данных**, а не относительно текущей даты.

## HTTP API

| Метод | Путь | Тело |
|---|---|---|
| GET | `/api/health` | — |
| POST | `/api/agent` | `{query, rows?, candidates?}` |
| POST | `/api/analytics` | `{rows?, period?: "latest" / "all" / "YYYY-MM"}` |
| POST | `/api/hr/score` | `{candidates?: [{name, experience, skills}]}` |
| POST | `/api/reply` | `{text, business?}` |
| POST | `/api/content-plan` | `{rows?}` |

`Content-Type: application/json`; лимит запроса 5 МБ. Ошибки возвращаются как `{error}` и HTTP 400 / 403 / 404 / 405 / 413 / 415. Чат использует API, если `/api/health` подтверждает сервер Orbit. Остальные интеракции используют тот же модуль `engine.js` локально. При статическом хостинге всё работает в браузере.

## Честные границы PoC

Это **демонстрация автономного рабочего процесса**, без LLM и без подключения к внешним CRM / Meta / HR API. Классификация намерения, ответы и тексты детерминированы. Неизвестный запрос вызывает подсказку о поддерживаемых задачах. Поддерживаются финансовый анализ (включая явный `2026-08` и «все периоды»), HR-оценка, контент-план и помощь с ответами.

Кнопка отправки создаёт запись только внутри локального симулятора; одобрение поста не публикует его. Даты контент-плана фиксированы на 19–23 октября 2026 для воспроизводимой презентации. Файлы не отправляются на внешние сервисы; при локальном Node-режиме аналитический запрос передаёт записи локальному API. Node-сервер не хранит данные на диске. История — до 20 задач и 30 диалогов; при переполнении localStorage интерфейс сообщит об этом.

Статическая опубликованная версия и локальное Node-приложение используют один фронтенд. Опубликованная версия работает в browser mock и сохраняет данные только в браузере посетителя. Node-бэкенд поставляется как запускаемый исходный код, в статический хостинг не входит.

Нет production-аутентификации, мультиарендности, планировщика, постоянной серверной БД и фонового автономного выполнения. Не загружайте реальные персональные данные в демонстрацию. Для внешних действий в production нужны роли, аудит, согласования и реальные API-адаптеры; этапы описаны в `ARCHITECTURE.md`.

### Оформление

Переключатель темы в верхней панели сохраняет светлый или графитовый тёмный режим. Шрифт Comfortaa, анимация орбиты и переходы поддерживают prefers-reduced-motion.
