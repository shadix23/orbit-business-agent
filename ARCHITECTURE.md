# Orbit Local Agent v2 — архитектура

## Границы компонентов

```text
Локальный браузер http://localhost:3000
  Существующие Dashboard / Agent / Analytics / HR / Inbox / SMM / Integrations
       │
  dist/local-client.js: API + поток NDJSON + AbortController
       │ same-origin HTTP
  server.mjs (127.0.0.1): конфигурация, границы HTTP, snapshot подключения
       │
  local/agent.mjs: план → tool call → observation → следующий шаг → ответ
       ├── Встроенный SQL-планировщик без LLM
       └── Локальная Ollama /api/chat, до 8 итераций и 12 вызовов
       │
  local/tools.mjs: allowlist инструментов, Python stdin/stdout, timeout / cancel
       │
  local/bridge.py
       ├── SQLite URI mode=ro + query_only + authorizer
       ├── get_db_schema: таблицы / представления / поля
       ├── execute_sql_query: один SELECT, параметры, лимиты
       ├── read_workspace_file: CSV / JSON / XLSX / TXT / MD
       └── list_workspace_files: инвентарь разрешённой папки
```

Чистая доменная логика остаётся в `dist/engine.js`. `local/context.mjs` связывает реальную схему и файлы с её контрактами. SQL строится из существующих полей, а не из имён, придуманных моделью. Пользователь может явно сопоставить любые названия date/revenue/cost и дополнительных полей.

## Состояние и источники

Workspace и выбранная SQLite задаются окружением или локальным UI. API делает снимок конфигурации перед каждой задачей. Реальные источники всегда читаются на сервере. Входные `rows` из браузера больше не используются сервером для аналитики. При недоступном сервере появляется ошибка подключения, имитация не запускается.

Данные компании не сохраняются в localStorage. Отчёты, графики, шорт-лист и черновики — память сессии; экспорт формирует скачиваемый файл по действию пользователя. Исходная папка и база не модифицируются агентом. Пример workspace создаётся отдельным `scripts/init-sample.mjs`, который не заменяет существующие файлы.

## События выполнения

`POST /api/agent` с `Accept: application/x-ndjson` передаёт `{event:"step",data:{id,kind,name,status,args,time,callId,elapsedMs,summary,error}}`, затем `{event:"result",data:...}` или `{event:"error",error:...}`. Парсер клиента буферизует неполные строки и декодирует UTF-8. Состояния running/completed/error обновляют одну запись инструмента. Это публичный журнал действий, не внутренние рассуждения модели.

Остановка закрывает поток и прерывает Python-процесс. SQL также имеет progress-handler с дедлайном. Бэкенд допускает до трёх одновременных задач агента. Ошибки не подменяются демо-результатами.

## SQLite

Открытие `file:...?...mode=ro`, `query_only`, `trusted_schema=OFF`, расширения отключены. Authorizer разрешает чтение и ограниченный набор стандартных функций; запись, ATTACH, PRAGMA из пользовательского SQL и расширения запрещены. `execute`, не `executescript`, исключает несколько операторов. Параметры значений — отдельный массив. Таблица финансов больше 10 000 строк требует reporting-view, а произвольный SELECT получает явный `truncated`.

## Filesystem и Excel

Пути относительны workspace; realpath проверяется на принадлежность папке. Скрытые пути и выход по symlink запрещены. Поддерживаемые расширения ограничены. XLSX читается через ZIP/XML стандартной библиотеки без извлечения файлов; есть лимит распакованного объёма. Формулы не исполняются, используются только кэшированные значения. Старый XLS не поддерживается.

## LLM

Встроенный планировщик делает ограниченный, проверяемый набор задач. Опциональная локальная Ollama получает JSON Schema-инструменты и результаты реальных вызовов. Имена инструментов сверяются с allowlist. Содержимое файлов и БД помечается как недоверенные данные. Бизнес-права ограничены чтением независимо от модели. Внешняя отправка и публикация в этом runtime отсутствуют.

## Развёртывание

Node + Python запускаются на ПК пользователя. Статический облачный хостинг не может заменить локальный runtime. Публичное демо v1 остаётся отдельным демонстрационным вариантом. Не нужно открывать локальный порт в интернет или предоставлять публичной странице мост к файловой системе.

PostgreSQL / MySQL можно добавить отдельными коннекторами за существующими `get_db_schema` и `execute_sql_query` с настоящей read-only ролью и transaction-level ограничениями. В текущем коде реализован SQLite.
